# 피보나치 수열 알고리즘 성능 프로파일링

## 1. 개요
본 과제는 피보나치 수열을 구하는 두 가지 방식인 **순환적 방법(Iterative)** 과 **재귀적 방법(Recursive)** 을 C언어로 구현하고, 입력값 $N$이 증가함에 따른 수행 시간을 프로파일링하여 성능 차이를 분석하는 것을 목적으로 합니다.

## 2. 알고리즘 구현 및 분석

### 2.1 순환적 방법 (Iterative)
* **방식:** `for` 반복문을 사용하여 처음 두 항(1, 1)부터 시작해 이전 두 항을 더해가는 방식입니다.
* **시간 복잡도:** $O(N)$ 
  * $N$이 증가할 때마다 덧셈 연산이 정직하게 1번씩만 추가되므로, 계산 시간이 $N$에 정비례하여 선형적으로 증가합니다.
* **측정 특이사항:** 연산 속도가 현대 CPU 환경에서 너무 빠르기 때문에, C언어의 `clock()` 함수 해상도 한계를 극복하고자 **동일한 N항 계산을 5,000,000번 반복 수행**한 총합 시간을 측정하여 프로파일링했습니다.

### 2.2 재귀적 방법 (Recursive)
* **방식:** 함수가 자기 자신을 다시 호출하여 `fibo(n-1) + fibo(n-2)`를 반환하는 하향식(Top-down) 방식입니다.
* **시간 복잡도:** $O(2^N)$ (엄밀히는 $O(1.618^N)$ )
  * 코드는 매우 직관적이고 간결하지만, 한 번 계산했던 하위 피보나치 항을 기억하지 못하고 중복해서 계속 호출하므로, $N$이 커질수록 함수 호출 횟수가 기하급수적으로 폭발합니다.

## 4. 결과 분석 및 고찰

프로파일링 결과, 이론적인 시간 복잡도인 $O(N)$과 $O(2^N)$의 극명한 차이를 실제 수행 시간으로 확인할 수 있었습니다.

1. **순환적 방법의 압도적 효율성:** 순환적 방법은 500만 번을 반복 수행했음에도 불구하고 $N$이 커질 때 시간 증가 폭이 매우 미미했습니다. 불필요한 중복 계산 없이 메모리(변수)를 갱신하며 전진하기 때문입니다.
2. **재귀적 방법의 지수적 폭발:** 반면 재귀적 방법은 $N=30$을 넘어서는 순간부터 그래프가 수직으로 솟구치는 지수적 증가(Exponential growth)를 보였습니다. 이는 함수 호출에 따른 오버헤드와 엄청난 양의 중복 계산이 시스템에 큰 부하를 주기 때문입니다.
3. **결론:** 재귀 함수는 점화식을 코드로 그대로 옮길 수 있어 가독성이 뛰어나지만, 피보나치 수열처럼 하위 문제가 심각하게 중복되는 알고리즘에서는 **순환적 방법**을 사용하는 것이 압도적으로 유리함을 확인했습니다.
